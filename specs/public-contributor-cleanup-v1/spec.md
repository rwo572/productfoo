# Public Contributor Cleanup V1

## Intent

Make the public productfoo repository usable and maintainable without its private predecessor. Complete the approved documentation audit cleanup and verify the public contributor journey before preparing, but not publishing, the first release.

## Current Understanding

- The owner approved audit items 1–11 and preparation of item 12 on 2026-10-16.
- The public repository contains the complete local CLI and bundled skills. Private history and services are not contributor prerequisites.
- Existing release metadata is pending reverification. No publication, visibility change, release tag, publisher setup, merge, or external notice is authorized by this packet.

## Requirements

### R-001 Self-contained contributor verification

- Priority: P1
- Risk: medium
- Confidence: high

A fresh public clone can install locked dependencies, build, run tests, regenerate and verify skills, validate documentation, and run npm run verify:public. Verification checks actual Git and npm contents with public rules and reviewed inventory; missing private manifests must not silently disable verification.

### R-002 One command authority

- Priority: P1
- Risk: medium
- Confidence: high

Generate Anthropic plugin launchers from the existing command contract. Check generated bytes for drift. Correct the quickstart task command and Codex refresh instructions. Keep installed-package and source-checkout instructions explicit.

### R-003 Accurate, consolidated public guidance

- Priority: P1
- Risk: low
- Confidence: high

Remove unsupported safety promises and stale private references. Align product intent, public design, runtime coverage, dependency guidance, example provenance and compatibility documentation with shipped behavior. Keep one task-oriented Markdown cheatsheet and generate its printable form. Preserve useful protocol specifications with explicit scope.

### R-004 Deliberate examples and fixtures

- Priority: P1
- Risk: low
- Confidence: high

Account for every example root. Keep useful examples with synthetic/experimental scope and limitations. Remove unsupported enforcement workarounds. Preserve test fixtures and coverage; experiments must be self-contained or explicitly historical, never require absent private evidence.

### R-005 Proof and release preparation

- Priority: P1
- Risk: medium
- Confidence: high

Add meaningful regression checks for executable instructions, available maintenance tools, links across shipped guidance and generated surfaces. Verify a fresh checkout and installed tarball with isolated configuration. Record exact candidate source and package evidence while preserving all existing publication gates. Source changes invalidate earlier evidence. Leave publication and visibility changes to a separate human decision.

## Decisions

- D-001 — (accepted, 2026-10-16) Implement the approved eleven cleanup items and prepare release evidence without publishing.
- D-002 — (accepted, 2026-10-16) Existing generated persona copies are required runtime artifacts; consolidate their source and generator rather than deleting them.
- D-003 — (accepted, 2026-10-16) Use repository facts and synthetic local tests only. No connector evidence, private source material, or customer data is added.

## Risks

- RISK-001 — Deleting old-looking examples breaks coverage. Check consumers before moving or removing anything.
- RISK-002 — Public verification becomes a weaker replacement for private checks. Test denial of unexpected package files and compiled Git artifacts.
- RISK-003 — Generated instructions drift after cleanup. Verify generated bytes and runnable documentation in CI.
- RISK-004 — Candidate evidence is confused with release approval. Keep status and remaining human actions explicit.

## Validation

- V-001 — Fresh npm ci, npm test, and npm run verify:public pass without private manifests or credentials.
- V-002 — Generator checks and documentation journey tests pass; planted drift or unsupported artifacts fail.
- V-003 — All example packets and this packet validate; implementation reconciles against this scope.
- V-004 — Review the named branch and exact tarball; release guard tests pass and no publication or visibility change occurs.

## Evidence

- Repository audit and owner approval in the initiating conversation; verified findings are represented by the requirements and regression tests.
- Public verification guide: docs/contributing/verification.md.
- Completion evidence is recorded in this packet's verification.md after checks run.

## Open Questions

- No decision blocks implementation. Publishing, repository visibility, release tagging and final merge remain separate actions.
