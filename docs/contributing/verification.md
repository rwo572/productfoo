# Verification

Run checks from the repository root before opening a pull request. Use the smallest
relevant checks while working, then run the complete suite before handoff.

## Build and test

```bash
npm run build
npm test
```

`npm test` rebuilds the TypeScript output and runs the compiled test suite.
Use Node.js 26.5.0 and npm 11.17.0 for contributor builds.
Use `npm ci` to install the locked contributor dependencies first.

## Repository boundaries

```bash
bin/foo self check
```

The self-check covers repository safety boundaries and reports advisory structure
or wording findings. Fix real secret findings; never weaken the scanner to make a
commit pass.

## productfoo Spec validation

After editing a productfoo Spec:

```bash
bin/foo asp validate specs/my-feature
```

After implementation changes tied to that spec:

```bash
bin/foo asp reconcile specs/my-feature --git-diff
```

Runnable public examples use the same validation contract from `examples/`.

## Generated files

Review generated output with:

```bash
npm run check:generated
```

This checks the swarm persona skills, command launchers, CLI reference,
third-party notices, and printable cheatsheet against their canonical inputs.
After editing those inputs, regenerate and inspect the changes:

```bash
npm run generate
npm run build
npm test
```

The Markdown cheatsheet is maintained at `docs/CHEATSHEET.md`; its HTML is
generated by `scripts/gen-cheatsheet.mjs`. Edit swarm persona template/data files
rather than rendered skills. Keep the bundled skill-tree anchor current after
skill changes. Generator checks do not prove model behavior.

## Agent adapters

Preview adapter setup without touching a contributor's real runtime configuration:

```bash
bin/foo agent setup --agent all --scope project --dry-run
```

Adapter generation tests should use temporary directories and compare only the
owned files with committed fixtures.

## Package contents

Run the self-contained public source/package verification:

```bash
npm run verify:public
```

It builds the public closure, checks repository and package inventories, and
smokes the installed tarball in isolated configuration. It requires no private
manifest, predecessor checkout, or productfoo credential. It is a contributor
check, not permission to publish.

After deliberate file additions or removals, follow the inventory update procedure
in [release preparation](release.md). Review and stage intended source files before
regenerating the inventories.

For a file-list inspection, `npm pack --dry-run --json` also shows the npm
payload. Review unexpected files and exclude private context, credentials,
service implementation, and stale generated output. Do not weaken the inventory
rules to make an unexplained file pass.

## Installed runtime compatibility

Build the package with the contributor toolchain, then install that tarball in
an isolated prefix using the Node/npm version under test. Run:

```bash
node scripts/test-installed-runtime.mjs /absolute/prefix/node_modules/productfoo
```

The script runs installed workflows with the selected Node binary, a fresh home,
and networking denied. CI schedules the Node/platform matrix described in
[runtime support](../runtime-support.md); the full source suite remains on the
pinned contributor toolchain.

## Documentation links

The tests check local Markdown links and anchors across README, docs, commands,
skills, plugins and examples, plus maintenance script paths and runnable quickstart
commands. External websites are not verified by these offline checks.

Also scan public copy for retired rollout language:

```bash
retired_copy='invite''-only|foo''-dist|alpha test''er|Open productfoo and productfoo Clo''ud|Does Open productfoo require productfoo Clo''ud|docs/foo-clo''ud.md'
rg -n "$retired_copy" README.md docs --glob '!docs/superpowers/**'
```

The command should return no matches.

## User-facing copy

Run the deterministic human-surface check before publishing substantially rewritten
copy:

```bash
bin/foo detect --human-surface < README.md
```

Repeat for user-facing pages under `docs/`. Rewrite any failing copy rather than
raising the threshold.

## Final diff review

```bash
git status --short
git diff --check
git diff -- README.md .gitignore docs
```

Confirm that the branch contains one coherent workstream and that unrelated local
or generated files are not staged.
