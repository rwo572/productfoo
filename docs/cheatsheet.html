productfoo quick reference

Install with npm install -g productfoo; see getting started for setup. In a built source checkout, substitute bin/foo for foo below. These commands help inspect work; they do not sandbox an agent or guarantee correctness. See getting started and the security model.

Set up an agent

foo doctor
foo agent setup --agent all --scope project --dry-run
foo agent setup --agent all --scope project --yes

Codex uses global scope and requires the Codex CLI on PATH:

foo agent setup --agent codex --scope global --dry-run
foo agent setup --agent codex --scope global --yes

After updating productfoo, repeat the Codex setup and start a new Codex task. Review setup output before applying it. See agent adapters for runtime-specific paths and ownership rules.

Maintain a spec

Use an existing packet and its actual task IDs in these examples:

foo asp validate specs/my-feature
foo asp task specs/my-feature T-001 --status done --proof "test or review link"
foo asp status specs/my-feature
foo asp reconcile specs/my-feature --git-diff
foo asp verify specs/my-feature
foo commit-trailer my-feature

A task marked done can still have proof pending. Validation checks structure; reconciliation reports alignment and gaps; verification inspects supporting proof. None substitutes for reviewing the implementation. See the spec guide.

Only agree a budget after reviewing the estimate and intended actions. An armed loop requires its contract and agreed budget; a declared cap is not a provider spending limit. Scans can miss private information. This repository does not ship Git hooks: run checks explicitly or configure your own integration.

Approve a connected source

foo source discover specs/my-feature --surface <surface.json>
foo source approve specs/my-feature --provider <provider> --connection <id> --scope <scope> --by <person>
foo source receipt specs/my-feature
foo source revoke specs/my-feature --provider <provider> --connection <id> --by <person>

Approval is scoped to the spec. It does not replace provider permissions or permit committing raw private material.

Report a problem locally

foo report add --expected "what should happen" --actual "what happened" --reproduction "steps to reproduce" --json
foo report show <capsule-id>
foo report delete <capsule-id> --approve <payload-digest>

Reports stay local in the public build. Review the exact bytes before sharing through another tool; prefer synthetic reproductions. The public package needs no productfoo account or service token.
