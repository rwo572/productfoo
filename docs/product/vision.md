# productfoo direction

productfoo helps people keep intent, decisions, evidence, and implementation
connected while working with coding agents. Its useful unit is a repository of
plain files that a person or another agent can inspect.

## Focus

- Shape a request into an agreed spec with explicit assumptions and boundaries.
- Keep approved evidence separate from accessible but unreviewed context.
- Make changes to scope visible while implementation proceeds.
- Compare the result with the agreement and show missing proof or drift.
- Keep the local workflow usable without a productfoo account or hosted service.

The project is intended for hands-on builders who want a reviewable record of
agent work. The framework supports human judgment; it does not establish that an
agent is correct or that an action is safe.

## Scope and maintenance

This is a personal open-source project. Hosted services, paid tiers, enterprise
rollouts, and a commercial roadmap are not commitments of this repository.
Changes are considered as time permits, based on demonstrated usefulness and the
cost of maintaining them. Forks can explore different directions under Apache-2.0.

Keep the CLI, skills, and spec format understandable together. Prefer fewer
concepts and explicit limitations over new surfaces that imply guarantees the
project cannot make.

See [project status and responsible use](../../README.md#project-status-and-responsible-use)
and the [security model](../security-model.md) for practical limits.
