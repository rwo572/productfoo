# productfoo plugin for Claude Code

The plugin exposes `/foo:*` commands in Claude Code. Its launchers invoke the
productfoo CLI and follow the command contract printed by that CLI. Command
behavior lives in `src/commandContract.ts`; the plugin contains generated
launchers, not a separate set of workflows.

## Install

Install Node.js 18 or newer and the productfoo CLI:

```bash
npm install -g productfoo
foo --version
```

Then register and install the Claude Code plugin:

```text
/plugin marketplace add rwo572/productfoo
/plugin install foo@foo-marketplace
```

The npm package includes the canonical skills. Their bundled integrity anchor
is checked locally; normal skill loading needs no skill server, productfoo token,
or network connection. Updating the CLI updates its bundled skills and command
handoffs. Refresh the plugin when its generated launcher metadata changes.

## Commands

- `/foo:init` — Read the project and choose a first move.
- `/foo:spec` — Shape work before implementation.
- `/foo:research` — Plan and gather public research with recorded evidence.
- `/foo:discovery` — Turn approved customer calls into reviewable evidence.
- `/foo:ideate` — Explore and stress-test product directions.
- `/foo:pitch` — Develop a Working Backwards PR/FAQ and opportunity assessment.
- `/foo:preview` — Prepare a Build Preview from a spec packet.
- `/foo:roast` — Critique a spec, prototype, or generated artifact.
- `/foo:bug` — Collect a local report of something broken in productfoo.

For arguments and operating behavior, use `foo commands list --json` or the
[canonical command documents](../../commands/). Bug reports stay local unless
an available send action receives fresh approval for its exact payload and
destination.

## Source development

From a source checkout, install dependencies and build before regenerating:

```bash
npm ci
npm run build
node scripts/build-anthropic-plugin.mjs
node scripts/build-anthropic-plugin.mjs --check
```

The generator uses the compiled command contract from `dist/`, so rebuild after
changing `src/commandContract.ts`. It emits the same skill launcher format used
by `foo agent setup`. Do not edit `skills/*/SKILL.md` in this plugin by hand.
The check compares every generated byte and reports missing, changed, or
unexpected launchers.

For local plugin testing, register the checkout in Claude Code:

```text
/plugin marketplace add /absolute/path/to/productfoo
/plugin install foo@foo-marketplace
```

CLI commands run by a plugin resolve `foo` on PATH. Use a deliberately installed
source build when testing CLI changes; changing plugin files alone does not
change the installed CLI. See [agent adapters](../../docs/agent-adapters.md) for
project and global adapter setup. Avoid enabling both this plugin and a native
`/foo:*` command adapter in the same Claude session; choose one command surface.

## Troubleshooting

If `foo` is missing, install the CLI and ensure its executable is on PATH:

```bash
command -v foo
foo --version
```

If skills fail to load, run `foo doctor` and follow its integrity or installation
repair instructions. Reinstall or update productfoo when its bundled files are
missing or changed; do not bypass the integrity check.

If commands do not appear, check that the marketplace plugin is enabled and
start a new Claude Code session. If launcher verification fails while developing,
rebuild and regenerate using the source-development commands above.
